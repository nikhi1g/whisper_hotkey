# whisper_hotkey 3.4.0: Two Choices

Recognition used to be four controls. It is one now.

## The problem

Engine, Model, Decoding, and Processing were four separate pickers, and a user
had to assemble a decision out of them using vocabulary they had no reason to
know. Nothing in "whisper.cpp Metal" or "Large-v3 Turbo Q5" or "Smart Decode"
tells you whether you are about to get a fast answer or an accurate one, which
is the only question anyone actually has.

Worse, the four were not independent. Decoding does nothing on a transducer.
The Model row means different things per engine. Processing interacts with
memory. The settings presented a sixteen-cell matrix over a space with far
fewer real combinations, which is what produced the run of interface bugs fixed
in 3.3.6.

## The change

Recognition now leads with two options:

| Preset | Runs | Word error rate | Latency |
| --- | --- | ---: | ---: |
| Fast | Parakeet 110M | 3.88% | 34 ms |
| Accurate | Parakeet 0.6B | 2.62% | 56 ms |

Engine, model, decoding profile, and processing mode fold behind an Advanced
disclosure. They are unchanged and still fully reachable.

Both presets resolve to Parakeet because it is ahead of every Whisper
configuration on accuracy and latency simultaneously, and as of this release
both checkpoints ship inside the app, so neither preset requires a download to
honor its label.

### Why two and not three

The obvious design is Fastest, Balanced, Most Accurate. It does not survive
contact with the measurements. Parakeet 0.6B is the most accurate option
available *and* answers in 56 ms, so Balanced and Most Accurate would resolve to
the same engine, the same checkpoint, and the same processing mode. A picker
whose options are not distinct is a picker that lies about having a choice.

Two presets is also what the tradeoff actually is: lowest latency and memory,
or best accuracy.

### Custom

A configuration matching neither preset reports **Custom**. It highlights no
segment, because none of them is true, and it forces the advanced controls open,
because those controls are the only explanation for the state. The disclosure
cannot be collapsed while Custom is in effect.

## The model lineup

Small and Medium English are retired.

**Small** had no remaining niche. Parakeet Fast beats it on size, speed, and
accuracy at once — 217 MB and 3.88% against Small's 466 MB and 8.59% — and Turbo
beats it on accuracy for only 82 MB more. It was dominated from both directions.

**Medium** was the largest and slowest model in the app and was not more
accurate than Turbo. It was also the only model that could not be bundled, which
made it the one setting that could trigger a 1.5 GB runtime download.

A saved selection of either migrates to Turbo, which is more accurate than both
and is bundled, rather than silently dropping to the default.

Base English and Large-v3 Turbo Q5 stay. Parakeet is a transducer and accepts no
prompt, so the internal dictionary and Pause Mode context only bias Whisper —
that is a real capability the Whisper engines have and Parakeet does not. Base
survives because it is the only genuinely lightweight tier, a quarter of Turbo's
size.

## Everything ships inside the app

Both Parakeet checkpoints are now bundled, joining Base and Turbo. The runtime
download catalog is empty: nothing is fetched during use. The install flow added
in 3.3.6 remains for any future model too large to bundle.

`ParakeetModelInstaller` prefers the bundled copy and falls back to the writable
cache. Verified by loading both checkpoints from the application bundle with no
FluidAudio cache present at all.

## Compatibility

Every engine and decoding profile behaves as before. The Advanced controls are
the same controls. Existing preferences are read unchanged except for Small and
Medium, which migrate as described above.
