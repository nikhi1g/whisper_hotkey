# whisper_hotkey 3.3.6: An Honest Interface

Version 3.3.0 added Parakeet and reorganized the Recognition settings around
it. This release fixes the interface bugs that shipped with it. They are all
the same defect wearing different clothes: a surface reporting something other
than what the app was doing.

## The freeze

Switching the Engine chip back and forth locked up Settings. Nothing crashed
and nothing was logged, which is what made it read as a hang.

`refresh()` applied the Model row's selection before rebuilding the row. The
row changes length with the engine — four whisper models, two Parakeet
checkpoints — so returning from Parakeet to a whisper engine asked a
two-segment control for segment three. AppKit raises `NSRangeException` there
rather than clamping, and because it happens inside the click handler, the rest
of `refresh()` never ran. The row kept Parakeet's chips, the engine read as
unchanged, and every later click re-entered the same path and died at the same
line.

It only bit in one direction. Metal to Parakeet shrinks four chips to two with
segment three selected, which survives. Parakeet back to Metal is the fatal
one, which is why switching *back and forth* was the trigger.

Three changes, so no future ordering change can bring it back: the row is
rebuilt before any selection is applied, the selection is dropped before the
segment count changes, and every write to the row goes through one
bounds-checked helper.

## Installing Parakeet is now a step you can see

Selecting Parakeet used to succeed instantly and defer the real cost. The first
dictation on a new checkpoint downloaded 220 MB or 440 MB inside
`transcribe()`, behind a Transcribing badge, with no progress bar, no cancel,
and no timeout.

That is now an explicit install at selection time, matching how the whisper
models that do not ship in the download are already handled: a confirmation
naming the size, the existing progress panel, a working Cancel, and an
indeterminate phase while Core ML compiles for this Mac. The engine or variant
is only selected once the install succeeds, so a cancelled or failed download
leaves the previous engine in place rather than selecting one that cannot run.

`ParakeetRuntime.load` no longer downloads at all. A missing checkpoint throws
with its path, so a dictation that somehow reaches one fails visibly instead of
stalling.

Cancelling is no longer treated as a failure. FluidAudio surfaces a cancelled
download as `NSURLErrorCancelled` rather than Swift's `CancellationError`, so
the old code fell through to the generic failure path and raised an alert
reading "The local Whisper helper failed: Parakeet download failed: cancelled"
— a whisper subprocess blamed for a Parakeet download, with one failure
sentence nested inside another.

## Surfaces that lied

- **User Guide.** It named the whisper model and offered Precision and Smart
  Decode as alternatives even while Parakeet was selected. Parakeet is a
  transducer and has no beam search for either to select.
- **Internal dictionary.** The row stayed fully interactive on Parakeet, so
  entries saved and displayed while never reaching the recognizer, because a
  transducer accepts no prompt. The row now states this. Entries are kept
  rather than cleared, since they still apply on every whisper engine.
- **Setup window.** It reported "Selected Whisper model" and "Whisper helper"
  as ready for an engine that runs neither.
- **Engine picker.** Availability was computed against the selected whisper
  model alone, so one uninstalled model greyed out every whisper engine at
  once. With Parakeet active the Model row shows Parakeet's own checkpoints, so
  there was no way left in the window to pick an installed whisper model, and
  no way back to a whisper engine. An engine is now available when some
  installed model can run it, and selecting one carries it to that model.

## Also

An app already running from `~/Applications` is no longer offered a move to
`/Applications` it does not need. `resolvingSymlinksInPath` keeps the trailing
slash on a directory it cannot resolve and drops it on one it can, and URL
equality is string-based, so the two spellings compared unequal wherever the
path did not exist.

## Compatibility

Recognition is unchanged. Every engine, model, and decoding profile behaves as
it did in 3.3.0, and the benchmark numbers still stand.
