# whisper_hotkey 4.2.8

Released: 2026-08-31

## AirPods capture recovery

- Observe `AVAudioEngineConfigurationChangeNotification` only for the recorder's owned engine.
- Recover on the existing serial capture queue because Core Audio's notification callback must not deallocate or synchronously tear down the engine.
- Remove the invalidated tap, reset the stopped engine, validate the current input format, reinstall a native-format tap, and restart the same recording.
- Preserve audio already written before the route transition.
- Retry one transient recovery failure after a bounded settling delay, then fail visibly and delete private audio through normal cleanup.
- Retain the `v4.2.7` dynamic converter and empty-buffer protections.

## Verification contract

- Engine-scoped notification observation and observer removal are covered by regression tests.
- Sequential 48 kHz, 16 kHz, and 24 kHz inputs must produce valid private 16 kHz mono output.
- The complete Swift suite, signed bundle, installed runtime, and built/installed hashes must pass.
- A physical AirPods dictation remains the decisive Bluetooth negotiation check.

## Distribution

Stable publication uses one Developer ID-signed, hardened, securely timestamped, notarized, and stapled `whisper_hotkey.dmg`. Gatekeeper assessment is mandatory. The website, GitHub release, and in-app updater use that DMG; no packaged application ZIP is published.

This first Developer ID build changes the designated requirement from the historical Apple Development identity, so existing users may need to grant Microphone, Accessibility, and Input Monitoring again. Preferences are unchanged. The application remains native arm64 for macOS 14 and later.
