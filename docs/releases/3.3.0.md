# whisper_hotkey 3.3.0: A Faster and More Accurate Engine

Version 3.3.0 adds Parakeet, and reorganizes the Recognition settings so they
describe what is actually running.

## Parakeet

Every recognition engine the app shipped until now was a different way to
execute whisper: whisper.cpp on Metal, whisper.cpp with a Core ML encoder, and
WhisperKit's native Core ML path. Parakeet is not another of those. It is
NVIDIA's FastConformer transducer, running on the Neural Engine through
[FluidAudio](https://github.com/FluidInference/FluidAudio), and it replaces
whisper rather than re-hosting it.

The reason to add it is that it is not a tradeoff. Measured on this
repository's own benchmark — 100 LibriSpeech utterances across test-clean and
test-other, Apple M5 Pro, warm model, scored with the same word error math as
the whisper benchmark:

| Engine | Combined | test-clean | test-other | Mean latency | Speed | Disk |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Turbo Q5 + Metal, Precision | 4.32% | 2.26% | 6.67% | 321 ms | 21.5x | 547 MB |
| Turbo Q5 + Metal, Smart Decode | 4.04% | 2.15% | 6.20% | 305 ms | 22.7x | 547 MB |
| Parakeet Fast | 3.88% | 2.36% | 5.61% | 34 ms | 206x | 219 MB |
| Parakeet Accurate | 2.62% | 1.54% | 3.86% | 56 ms | 123x | 443 MB |

Parakeet Accurate cuts the error rate of the previous best option by 39% while
answering 5.7 times faster. Parakeet Fast is a 110M model, less than half the
size of Small English, and is still more accurate than every whisper model in
the app.

Reproduce these numbers with the harness in `Benchmarks/Parakeet/`. It is a
separate package so that FluidAudio never links into a shipped bundle.

## The Recognition section is reorganized

Adding a fourth engine exposed that the section was describing a matrix that
does not exist. Four models by four engines implies sixteen combinations, but
whisper has four sizes and three runtimes while Parakeet has two checkpoints
and one. Three changes fix that.

**Engine comes first.** It decides which models exist and whether Decoding
means anything, so the section now reads in dependency order rather than
cutting across it.

**The Model row belongs to the selected engine.** Choosing Parakeet replaces
whisper's Base, Small, Medium, and Turbo with Parakeet's own Fast and Accurate.
Previously the whisper chips remapped onto Parakeet checkpoints, so a chip
labelled Turbo selected a model that is not Turbo, and Small, Medium, and Turbo
all selected the same checkpoint while appearing to be three distinct choices.

**Decoding is hidden, not greyed, when it does not apply.** A disabled
segmented control still paints its selection, so Precision appeared active on
engines with no beam search. This affects WhisperKit as well as Parakeet. The
stored profile survives, so returning to a whisper.cpp engine restores it.

Parakeet also keeps its own saved model selection, so switching engines back
and forth no longer overwrites the other engine's choice.

## What Parakeet gives up

- **No decoding profiles.** A transducer has no beam search, so neither
  Precision nor Smart Decode has anything to select.
- **No prompt conditioning.** whisper accepts an initial prompt, which is how
  the internal dictionary and the Pause Mode context tail bias recognition. A
  transducer takes no prompt, so both are dropped on this engine. They still
  apply on every whisper engine, which is one reason all of them remain
  available and unchanged.

## Installing models

Parakeet checkpoints download on first use into
`~/Library/Application Support/FluidAudio/Models/`, so `run.sh` installs
nothing for this engine and `./run.sh --engine parakeet` only selects it. The
first dictation after selecting Parakeet waits on that fetch.

## Compatibility

Every existing engine, model, and decoding profile is unchanged and still
selectable. Existing preferences are read as before; Parakeet's selection is a
new key that defaults to Accurate.
